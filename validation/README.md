# Валидация релятивистского полёта (interstellar)

Пакет сверяет **код проекта** с аналитическими эталонами специальной теории
относительности и слабого гравитационного поля. «Simulated» — это выход реальных
модулей: `js/physics/ship.js` (`Ship.step`: интегратор specific-momentum
`w = γv`, собственное время τ), `js/physics/relativity.js` (`dopplerFactor`,
`gammaFromV`, `momentumFromV`), `js/physics/gravity.js` (через `Ship.step`) и
`js/data/bodies.js` (GM, радиусы). Формулы на стороне «simulated» не переписываются;
эталоны записаны независимо в `validate.mjs`. Продакшн-код `js/` не изменён.

## Как воспроизвести

```
bash validation/run.sh            # из корня репо: все кейсы, пишет validation/results/*
bash validation/run.sh --check    # не пишет; сверяет со ЗАКОММИЧЕННЫМИ results (детект дрейфа)
```

Код возврата 1, если любой кейс превысил допуск (или при `--check` результаты
разошлись с закоммиченными). Нужен только `node` (>=18); Three.js вендорен.

Файлы в `validation/results/`:
- `table.md`, `table.csv`, `results.json` — **байт-детерминированны** (числа в формате
  `toExponential(6)`); можно сравнивать `diff` между прогонами/машинами.
- `env.json` — версия node, git-коммит, дата. Только здесь недетерминированные данные.

## Как читать таблицу

Колонки: `case, quantity, analytic, simulated, abs_err, rel_err, tolerance, status`.
- `rel_err = |sim − an| / |an|`; если `an = 0` — величина намеренно нормирована
  (`w/c`, `x/x_turnaround`), и `rel_err = abs_err`.
- `tolerance`: `rel<=X` — условие на `rel_err`; `value>=X` — для порядка сходимости
  (проверяется само наблюдаемое значение).
- `status`: `PASS`, `FAIL` (валит прогон), `NOT_COVERED` (честно не покрыто кодом).

## Кейсы и эталоны

**A. Гиперболическое движение** (постоянное собственное ускорение α из покоя, 1D,
`Ship` в режиме arcade, `maxAccelArcade = α`, без тел). Эталоны:
γ = cosh(ατ/c), β = tanh(ατ/c), t = (c/α) sinh(ατ/c), x = (c²/α)(cosh(ατ/c) − 1), w = γv = αt.
Интегратор шагает по координатному времени, поэтому гоним T = t(τ*) и сравниваем
состояние/часы корабля при τ*. Режимы: A1 — 1 g, τ = 1 год; A2 — 1000 g до γ = 13
(та же точка, что в `tests/longitudinal.regression.test.mjs`). A3 — сходимость:
задача A1 при N = 1000/2000/4000 шагах, наблюдаемый порядок для τ и x.

**B. Парадокс близнецов.** Профиль: разгон ατ₁ → дрейф τc → торможение τ₁ → разгон
назад τ₁ → дрейф τc → торможение τ₁ (1 g, τ₁ = 2 года, τc = 1 год). Эталоны:
τ_ship = 4τ₁ + 2τc; t_earth = 4(c/α) sinh(ατ₁/c) + 2 cosh(ατ₁/c)·τc; Δτ = t_earth − τ_ship;
x в точке разворота = 2(c²/α)(cosh−1) + c·sinh(ατ₁/c)·τc; в конце x ≈ 0, w ≈ 0.
Координатные длительности фаз (T₁ = (c/α) sinh, дрейф = τc·cosh) задают расписание,
поэтому `t_earth` — независимая переменная прогона, а проверяются τ, Δτ, x, w.
B2 — без ускорений: начальная скорость через `momentumFromV`, τ = t/γ, x = βct
(β = 0.8 и 0.99).

**C. Красное смещение.**
- C1: `dopplerFactor(vRadial)`. **Конвенция знака (из кода):** `vRadial > 0` — источник
  *приближается*; возвращается ν_obs/ν_src = √((1+β)/(1−β)) (>1 — синее смещение),
  `vRadial < 0` — удаление, √((1−β)/(1+β)) = 1/D. Сетка β ∈ {0.1, 0.5, 0.9, 0.99}.
- C2: поперечный эффект 1/γ — **не покрыт**: угловая форма Доплера
  D = √(1−β²)/(1−β cosθ') есть только в GLSL (`relativisticPass.js`), в node-JS её нет.
- C3: гравитационное замедление времени. Через реальный `Ship.step` (один шаг 1 мс у
  одного тела, `properTime`) сравнивается эффект 1 − dτ/dt с точным Шварцшильдом
  1 − √(1 − 2GM/(rc²)) (Земля — поверхность; Солнце — поверхность и 1 а.е.).
  GM и радиусы берутся из `js/data/bodies.js` и **сами не валидируются**.

## Допуски и обоснование (выведены из оценки ошибки, не подогнаны)

| Величины | Допуск | Обоснование |
|---|---|---|
| γ, β, w, τ в инерциальном полёте | 64·N·ε | у схемы нет ошибки усечения (`w += a·dt` точно при const a, дрейф при a=0 точен); остаётся только накопление округлений N сложений, ε = 2⁻⁵²; 64 — запас на сокращение в 1−β² (~γ²ε) (B2 дополнительно ×γ²) |
| τ, x при ускорении | 2·\|dt/2·(f(b)−f(a)) + dt²/12·(f′(b)−f′(a))\|/\|эталон\| + 64·N·ε | схема `Ship.step` — правило правых прямоугольников для точного f(t) (f = v или 1/γ) на каждой фазе постоянной тяги; формула Эйлера–Маклорена даёт ошибку суммы, множитель 2 — запас на отброшенный O(dt⁴). Это предсказание схемы: деградация точности/порядка ловится, улучшение проходит |
| порядок сходимости | ≥ 0.9 | схема первого порядка (ожидается 1.0); 0.1 — запас на пре-асимптотику |
| Δτ, x_final | сумма фазовых оценок как выше (знаки сохраняются, в симметричном профиле первый порядок взаимно сокращается) + 64·N·ε·масштаб | то же правило, применённое ко всему профилю |
| `dopplerFactor` | 4ε/(1−β²) + 8ε | входное квантование `vRadial = β·C`, затем `/C` даёт \|δb\| ≤ εβ; dD/D = δb/(1−b²) |
| гравитационное замедление | u + 4ε/u, u = GM/(rc²) = \|Φ\|/c² | допуск на погрешность слабого поля O((Φ/c²)²) в dτ/dt, отнесённый к эффекту u; плюс шум измерения ε/u (эффект — разность чисел около 1). Код использует √(1+2Φ/c²−β²), что для покоя совпадает с Шварцшильдом точно, поэтому фактическое расхождение ~ε/u, много меньше допуска |

Допуск на гравитацию — самый слабый: он отражает априорную оценку слабого поля, а не
возможности кода (реально ошибка ≈ 1e-7…1e-11 от эффекта).

## Что НЕ проверено (ограничения)

- Аберрация и Доплер в шейдере (GLSL в `relativisticPass.js`): не исполняются в node;
  `aberratedCos` как JS-зеркало покрыт отдельно в `tests/relativity.test.mjs`.
- Поперечный Доплер 1/γ (см. C2).
- ОТО за пределами слабого поля: сильное поле, вращающиеся тела, orbital GR-прецессия,
  геодезический вклад гравитации в `w` (`dwGrav`) — не сверялись с эталоном.
- Поперечная (⊥ к v) тяга, дрэг, расход топлива в режиме realistic.
- GM, радиусы и орбитальные элементы тел — входные данные, не валидируются.
- Времена за пределами 1D-кейсов; эталоны специально одномерные.
